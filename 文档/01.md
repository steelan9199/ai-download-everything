你是一名资深全栈工程师 + 浏览器自动化/多媒体专家。用中文交流，帮我从零开发一个 Windows 11 上的桌面应用（单用户自用，不需要多账号）。

【产品目标】
给"完全不懂代码的普通人"用的视频下载器：粘贴网址 → 点下载 → 得到完整视频文件。
难点：目标站用了 Cloudflare 反爬（Bot Fight Mode，直连/工具会 403）+ HLS"直播式滑窗"防盗链（只暴露最近几个分片、无 EXT-X-ENDLIST），普通工具要么 403、要么只抓到几秒。

【核心设计哲学：三层分工，严格省 token】
软件分三个"角色"，各司其职，绝不让大模型做不该它做的事：
1. 程序内置代码（免费、不限次数）：打开页面、拦截网络、抓 m3u8 与分片、下载、合并、断点续传、失败重试、查规则表、跑已沉淀的脚本——这些是确定性代码，跑多少遍都不花 token。
2. 人工的眼睛与手（免费且最快）：负责"看画面、认内容"这类视觉判断（这是大模型最烧 token 的部分），并完成必须真人才能做的动作——观察视频有没有正常播放、登录、点验证码、扫码、成人确认等。
3. 大模型（唯一烧 token 的部分）：扮演"按需顾问/工具制造者"——遇到没见过的情况时，可以（在受限环境里）自行编写/修改脚本去抓取数据、处理异常，并执行；但只在规则表、点选式人工反馈都搞不定、且确实需要"动脑+写代码"时才被调用。每次只解决一件最小的事，绝不无限循环、不做多轮闲聊、不自己瞎跑全量探索。

【技术选型（必须遵守）】
- 桌面框架：Electron（内嵌 Chromium 作为浏览器引擎，靠它过 Cloudflare）。渲染层用 Vue3 + 简洁 UI；后端脚本只用 Node.js（Electron 自带运行时），不使用 Python。
- 最大化复用用户本机环境，一律"外置为可配置路径"，绝不把第三方二进制塞进包：
  - ffmpeg：分片合并、转封装、音视频合成。
  - yt-dlp.exe：主力下载引擎——能直接下的普通站（YouTube 等）全交给它；只有 Cloudflare 难站才走 Electron 内嵌浏览器拦截。
- 抓取难站时：用 Electron 内嵌浏览器的 CDP / Network 拦截 .m3u8 与分片（.mp4/.ts），按序写盘后交给本地 ffmpeg 合并。
- 大模型：做成可配置（OpenAI 兼容接口，支持 OpenAI / DeepSeek / Kimi / 通义等，留 API Key + baseURL 配置项），默认关闭自动调用（auto-call 关），只在"问 AI"按钮或异常兜底时触发。

【AI 自写脚本的能力与安全边界（重要）】
大模型不只是"回建议"，还能在受限环境中生成脚本并执行，用于抓数据、解析页面、处理异常。必须按如下安全模型实现：
1. 默认白名单：AI 生成的脚本只能读写"下载目录"（工作目录），只能调用 ffmpeg / yt-dlp.exe / 发起 HTTP 请求。越界动作（读写目录外文件、跑其他命令）一律拦截并弹窗请用户确认。
2. "临时授权本机全权"开关：某些情况需要读写别的文件/跑其它命令，用户可在设置页或弹窗里临时打开；该开关默认关闭、作用域默认限本次任务，任务结束或超时自动恢复白名单，并在高级模式里提示用户"当前已临时全权，可关闭"。
3. 执行确认：白名单内的脚本直接自动执行（不打扰人）；越界/全权脚本先弹确认再执行。
4. 脚本沉淀：AI 每攻克一个新站/新问题，把可复用的脚本存成"站点规则库"，下次同站直接复用、不再调大模型——最省 token。

【设置页】
提供"设置"页，集中配置并复用本机环境：下载目录（必填，默认给一个合理路径 + "浏览"定位）、ffmpeg 路径、yt-dlp.exe 路径、大模型 API Key / baseURL、"临时授权本机全权"开关。所有路径支持手动填写 + 浏览。

【启动自检】
启动时自动探测 ffmpeg、yt-dlp.exe 是否存在、路径是否可用、下载目录是否可写；缺失/失效时弹"指引"：给出下载链接、安装命令、以及"去填写路径"入口。绝不往包里塞二进制，缺失就引导用户，不报错装死。

【下载主流程（程序主导，人按需配合）】
1. 用户粘贴网址 → 先尝试用本机 yt-dlp.exe 直接下载（覆盖绝大多数普通站，省事省 token）。
2. yt-dlp 失败/命中目标难站（Cloudflare、m3u8 滑窗等）→ 切到 Electron 内嵌浏览器打开播放页并引导/自动点播放，后台拦截网络抓 .m3u8 和分片（纯代码，人不操心）。
3. 可引导用户"低成本喂关键信息"（可选，加速成功）：用猫抓/F12 复制 m3u8 链接、或 Copy as cURL 粘贴进来。
4. 程序按内置逻辑高速并发下载分片（不依赖播放速度；尽量拿全部分片，拿不到就边播边存）。
5. ffmpeg 合并输出到"下载目录"，显示进度与结果。

【错误处理：先查规则表 → 再请人看一眼 → 再让 AI 写脚本 → 实在不行请人手动】
1. 出错先查内置"错误码 → 处理方案"规则表与"站点规则库"（本地、免费、即时应答）：命中就直接用已沉淀的脚本/方案执行。403/反爬 → 引导人拿 Cookie/cf_clearance 或换直链；token 过期/分片 403 → 自动重拉 playlist 并续传；滑窗只拿到几秒 → 引导人用猫抓复制具体画质 m3u8 重试。
2. 规则表/规则库查不到 → 生成极短的本地"诊断摘要"（状态码 + 出错 URL + 一句可能原因），先请用户"看一眼画面"：用【点选式问题】让用户选择眼前的情况（如"视频有没有在播放：在播/转圈/报错"、"是否弹出一个写着验证的框：是/否"），每个点选题下方固定带一个【其他/自定义】文本框，供用户用大白话补充描述。
3. 点选+补充仍无解 → 才调大模型，发【精简结构化摘要】+ 用户描述，让它在受限白名单内写一个最小脚本去抓取/验证/处理；成功后把该脚本沉淀进规则库。
4. 大模型也搞不定 → 转为纯人工指引（给清晰步骤），不无限循环烧 token。

【关键场景都要覆盖】
- Cloudflare 403 / Bot Fight Mode：Electron 内嵌 Chromium 真实指纹 + 持久化 profile 复用 Cookie/cf_clearance。
- HLS 直播滑窗：确保抓到完整视频而非只抓最近几秒；给出"边播边存（实时）"与"破解定位/会话参数全速抓取"两条路径并说明各自取舍。
- AES-128 加密流（EXT-X-KEY）：自动下 key 解密
- 断点续传、失败重试、多线程、>1GB 大文件稳定性。
